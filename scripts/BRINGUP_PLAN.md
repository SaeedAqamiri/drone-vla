# نقشه راه: از FPV خریداری‌شده تا ناوبری GPS-denied و هم‌خلبان VLA

> وضعیت پایه: `navlab` در شبیه‌ساز قبلاً EV تزریق‌شده، map-matching (خطای ۰.۲–۲.۹m)،
> Fusion2D و BOM سخت‌افزار را اثبات کرده است. این سند مسیر «سیم‌کشی به دنیای واقعی» است.

---

## ۰) شناسایی پهپاد (اولین کار، بدون هیچ ابزار)

### چک‌لیست فیزیکی
1. **بازکردن کانوپی** و خواندن نوشته‌ی روی برد: معمولاً `SPEEDYBEE F405 V4`،
   `MATEKSYS F405`، `KAKUTE H7`، `BETAFLIGHTF405`، `FLYWOO` و... → این «target» برد است.
2. ثبت مدل **رادیو رسیور** (ELRS/CRSF؟ SBUS؟)، **دوربین/VTX** (آنالوگ؟ DJI O3؟ Walksnail؟)،
   تعداد/سایز موتور، پروتکل ESC (DShot600؟)، باتری (4S/6S).
3. عکس از برچسب باتری/برد بگیر (برای مراجعه‌ی بعدی).

### اتصال به کامپیوتر
1. دانلود **Betaflight Configurator** (ویندوز) از GitHub رسمی + درایورهای USB (اگر لازم شد).
2. پهپاد را **بدون پروانه** با کابل USB به PC وصل کن (باتری لازم نیست؛ USB تغذیه می‌دهد).
3. در Configurator:
   - تب **Firmware Flasher** → نام target و نسخه‌ی فریمور (مثلاً `SPEEDYBEEF405V4 4.5.x`)
   - تب **Setup** → وضعیت سنسورها: gyro, accel, baro, mag, GPS
   - تب **Ports** → کدام UART برای رسیور است و پروتکلش
   - تب **Receiver** → پروتکل و کانال‌ها
4. اگر Configurator وصل نشد → برد **INav** است (با INav Configurator امتحان کن) یا بریک/FTDI لازم دارد.

### تصمیم کلیدی (مهم‌ترین تصمیم پروژه)
| وضعیت FC | مسیر |
|---|---|
| target در لیست PX4/ArduPilot هست (مثل Kakute H7) | می‌شود PX4 فلش کرد و همان برد کنترلر خودمختار شود (Betaflight را از دست می‌دهی) |
| target پشتیبانی نمی‌شود (اکثر F405های ارزان) | **پیشنهاد: برد را برای پرواز دستی نگه دار** و یک **Pixhawk 6C Mini** برای خودمختاری روی همان فریم بگذار (طبق BOM موجود) |
| تردید | Pixhawk 6C Mini مسیر مطمئن و مستند است؛ هزینه ~۱۰۰–۱۵۰ دلار |

> ⚠ Betaflight اصلاً offboard/MAVLink و کنترل از کامپیوتر را پشتیبانی نمی‌کند.
> هدف «کنترل از PC/بورد همراه» فقط با PX4 یا ArduPilot معنا دارد.

### ۰.۱) نتیجهٔ شناسایی (۲۰۲۶-۱۱-۰۴) — خودکار از USB + عکس‌ها

| مورد | مقدار | منبع |
|---|---|---|
| FC | **GEPRC F405** (board id `S405`, MCU STM32F405) | MSP روی COM4 (`VID_0483&PID_5740`) |
| فریمور | **Betaflight 4.4.3** — build `Jun 25 2024 07:01:55` | MSP_FC_VERSION / BUILD_INFO |
| میکسر | کواد-X، ۴ موتور، ۱۴ پل، گاز ۱۰۷۰–۲۰۰۰ | MSP_MIXER / MOTOR_CONFIG |
| رسیور (تنظیم) | **SRXL2** (کد ۹) | MSP_RX_CONFIG |
| سنسورهای تشخیص‌داده‌شده | فقط ACC + GYRO (`0x21`) | MSP_STATUS |
| فریم | کواد ۷ اینچی لانگ‌رنج، بازوهای باریک بلند، دو صفحهٔ کربنی، استیکر `PASSED QC` | عکس |
| برد پایین (عقب) | سیلک‌اسکرین: `VBAT` `CURRENT` `5V` `GND` `PWR` `LED` `ARM` `BZ±` **`MS5611`** **`LIDAR`** `I2C` `CTRL` | عکس |
| رسیور فیزیکی | برد کوچک در دم با **دو آنتن دایپل V شکل** + LED قرمز (دایورسیتی) — **مارک نامشخص** | عکس |
| جعبهٔ سفید بالای فریم | قطعهٔ پرینت‌شده (احتمالاً جای GPS) — خالی/نامشخص | عکس |

**نکات عملی:**
- پورت **`LIDAR`** روی FC وجود دارد → رنج‌فایندر برای قدم ۳ (GPS-denied) آمادهٔ اتصال است.
- **`MS5611`** (بارومتر) روی برد هست ولی Betaflight بارو را detect نکرد → در Configurator تب Setup چک شود
  (`baro_hardware`, I2C). اگر خراب باشد، PX4 هم بارو نخواهد داشت (برای hover بی‌اهمیت، برای ارتفاع مهم).
- **رسیور SRXL2** با ELRS نمی‌خواند؛ یا تنظیم اشتباه است یا رسیور اسپکتروم است → قبل از خرید رادیو
  باید مارک رسیور از نزدیک خوانده شود.

### ۰.۲) جابه‌جایی اتوپایلوت: چه چیزی می‌ماند، چه چیزی عوض می‌شود

| قطعه | سرنوشت |
|---|---|
| فریم، موتورها، ۴-در-۱ ESC، دوربین FPV، VTX | ✅ می‌مانند (DShot با PX4 سازگار است) |
| رسیور | ⚠ اگر CRSF/ELRS باشد می‌ماند؛ SRXL2/DSM بهتر است عوض شود |
| GEPRC F405 | ❌ برداشته می‌شود |
| Pixhawk 6C Mini | 🆕 |
| Power Module (۵.۳V + Vbat/Current) | 🆕 **الزامی** |
| GPS + قطبنما | 🆕 الزامی (برای آرم/مود در PX4) |
| تله‌متری رادیویی | 🆕 توصیه‌شده (QGC روی زمین) |

سه سناریو: **A)** فقط FC عوض شود (ESC می‌ماند) — **B)** اگر برد AIO باشد، ESC هم لازم است —
**C)** ایرفریم دوم ساخته شود و پهپاد فعلی دست‌نخورده بماند ✅ (توصیه: ریسک صفر برای پهپاد سالم).

نکات: الگوی نصب Pixhawk 6C Mini با استک ۳۰.۵×۳۰.۵ یکی نیست → آداپتور/براکت؛ نصب روی **فوم نرم**
(ارتعاش)؛ مهاجرت پارامتر از Betaflight وجود ندارد (کالیبراسیون از صفر، ~۲–۳ ساعت + یک روز تست).

## ۰.۵) رادیو و تمرین خلبانی دستی (بدونش جلو نرو)

- **خرید پیشنهادی:** RadioMaster **Pocket ELRS 2.4GHz** (ارزان‌ترین گزینه‌ی خوب، هال-گیمبال،
  داخلی ELRS) یا RadioMaster **Boxer** اگر بودجه بیشتر داری. هر دو با کابل USB به PC
  به‌عنوان **Joystick** کار می‌کنند → مستقیم در شبیه‌ساز FPV.
- **شبیه‌ساز FPV:** Velocidrone (~$23) یا Liftoff (~$20)؛ رایگان: Tryp FPV.
  حداقل ۱۰ ساعت تمرین قبل از پرواز واقعی.
- لوازم جانبی: ۲–۳ باتری، شارژر، پروانه‌ی یدکی، و بعداً گوگل.

## ۱) ایستگاه شبیه‌سازی (در حال نصب روی این PC)

- **WSL2 + Ubuntu 24.04** (جدا از Ubuntu 26.04 فعلی — چون استک رباتیک روی 26.04 ریسک دارد)
- داخلش: **Gazebo Harmonic + PX4 SITL** + `env_flight` (mavsdk<4, pymavlink, navlab deps)
- GUI گازبو از طریق **WSLg** روی ویندوز بالا می‌آید (Win10 build 19045 پشتیبانی می‌کند).
- اجرا:
  ```bash

  cd ~/drone-vla && ~/env_flight/bin/python -m navlab   # http://127.0.0.1:8080
  cd ~/PX4-Autopilot && make px4_sitl gz_x500           # GUI
  # یا HEADLESS=1 برای بدون پنجره
  ```

### ۱.۱) نکات بیلد PX4 روی شبکهٔ ایران (تجربهٔ واقعی ۲۰۲۶-۱۱-۰۴)

| مشکل | نشانه | راه‌حل |
|---|---|---|
| submodule های `voxl2` روی gitlab.com | `error 403` و توقف کل بیلد | `GIT_SUBMODULES_ARE_EVIL=1 make px4_sitl_default` (فلگ رسمی خود PX4) |
| TLS وصل می‌شود ولی داده نمی‌آید | پروسه `git-remote-https` با `ESTAB` و ۰ بایت | `git config http.lowSpeedLimit 2000` + `http.lowSpeedTime 30` و `timeout -k 5` |
| `timeout` فرآیند git را نمی‌کشد | submodule ساعت‌ها گیر می‌کند | `timeout -k 5` + بعدش `pkill -9 -f 'git[-]remote-https'` |
| کلون قبلیِ kill شده مسیر را پاک می‌کند | سورس ناگهان خالی می‌شود | قبل از هر تلاش: `pkill -9 -f 'git[ ]clone'` |
| بررسی «submodule موجود است» با `ls` | فقط `.git` وجود دارد ولی پوشه خالی است | `ls -A dir \| grep -v '^\.git$' \| wc -l` باید > ۲ باشد |
| `PX4-OpticalFlow` submodule تودرتو دارد | `klt_feature_tracker` ندارد → خطای CMake | `git -C .../PX4-OpticalFlow submodule update --init --recursive --depth 1` |
| الگوی `pkill` خودِ دستور را هم می‌کشد | خروجی خالی و exit code 1 | از براکت استفاده کن: `pkill -f 'px4_fina[l].sh'` |

اسنپ‌شات محافظ: `/home/drone/px4_src_snapshot.tar.gz` (بعد از کلون موفق ساخته می‌شود).

## ۲) بورد همراه (RPi5) و اتصال MAVLink

1. Pixhawk 6C به RPi5 از طریق UART (TELEM2 → `/dev/ttyAMA0`).
2. پارامترهای PX4: `MAV_1_CONFIG=TELEM2`, `SER_TEL2_BAUD=921600`.
3. تست bench (بدون پروانه): MAVSDK تله‌متری → arm → takeoff → land روی میز/قاب.
4. سپس **HITL** با اسکلت موجود در `navlab/hardware.py` (چک‌لیست آماده است).
5. در شبیه‌ساز: همان کد MAVSDK بدون تغییر به SITL وصل می‌شود (همان قرارداد).

## ۳) ناوبری بدون GPS

### در شبیه‌ساز (تقریباً تمام‌شده)
- ✅ تزریق EV + map-matching + baro height (NOTES 13.8)
- ⏳ باقی‌مانده: **کنترل offboard local NED** با گیت ایمنی (حداکثر سرعت/فاصله، setpoint ثابت bench)
- ⏳ جایگزینی تدریجی truth با خروجی واقعی localizer در کل مسیر

### روی پهپاد واقعی
- سنسورها: دوربین رو به پایین + **PMW3901** (optical flow) + **VL53L1X** (rangefinder)
- همان پارامترهای اثبات‌شده: `EKF2_EV_CTRL`, `EKF2_HGT_REF`, `EKF2_GPS_CTRL=0`, `COM_ARM_WO_GPS=1`
- مسیر جایگزین: map-matching با نقشه‌ی از قبل پرواز‌شده (نیازمند دوربین خوب + همگام‌سازی زمان)
- **معیار پذیرش:** هاور ۳۰m، ۴ waypoint، خطای < ۳m، بدون failsafe/blind-land

## ۴) هم‌خلبان VLA (FLUX 3 Action)

- **اجرا:** روی ایستگاه زمینی (RTX 2080 8GB با nf4 ≈ ۶.۸GB peak) یا آنبورد با
  **Jetson Orin NX 16GB** (⚠ Orin Nano 8GB برای مدل ۷B تنگ است؛ RPi5 اصلاً نمی‌تواند).
- **قرارداد اکشن:** `[fwd, lat, up, yaw]` در [-1,1] @ 15Hz → تبدیل به velocity setpoint offboard.
- **نقش:** هم‌خلبان (co-pilot) نه خلبان اصلی → حق وتوی خلبان + geofence + سقف سرعت + kill switch.
- **داده:** ۳۰۰–۸۰۰ اپیزود از Gazebo/Isaac → fine-tune روی GPU کرایه‌ای (RunPod 4090).
- **محدودیت واقعی:** ~۱.۱s به‌ازای هر پلن ۳۲ گامی → برای واکنش لحظه‌ای کافی نیست؛
  باید با execution horizon کوتاه و کنترلر پایه ترکیب شود.
